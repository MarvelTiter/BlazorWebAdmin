## 调研：路由/程序集扫描 ScanRazorLibraryAssembly 的 AOT 化可行性与 Razor 可见性实测

### 结论（已实测验证，非推测）

在临时目录搭了隔离探针工程（gen=netstandard2.0 源生成器 + app=Microsoft.NET.Sdk.Razor net10.0），实测结果：

1. **源生成器在分析阶段完全看不到 Razor 生成的语法树。**
   探针打印的 6 棵可见树：`Plain.cs` / `EmbeddedAttribute.cs` / `ValidatableTypeAttribute.cs` /
   `.NETCoreApp,Version=v10.0.AssemblyAttributes.cs` / `App.AssemblyInfo.cs` / `App.GlobalUsings.g.cs`
   —— 无一棵是 Razor 产物。`[Route]` 类只命中手写在 `.cs` 里的 `ProbeApp.PlainPage`，
   `@page "/probe"` 的 razor 组件一个都没找到。
   原因：.NET 6+ Razor 编译本身就是增量源生成器 `RazorSourceGenerator`；Roslyn 在所有生成器跑完后
   才把输出合并进 Compilation，因此生成器互相看不到对方产物。

2. **但生成器输出的代码里可以引用 Razor 生成的类型。**
   探针 emit 了 `typeof(global::ProbeApp.Components.Pages.TestRazorComponent)`，**编译 0 错误**。
   所有生成器的输出树最终在同一 Compilation 里一起绑定。
   ⇒ 可以从 razor 文件路径推算类型全名后放心 `typeof()`，且 AOT 下能硬引用 root 住类型防裁剪。

### 本仓库暴露面

17 个带 `@page` 的 razor 页，其中 15 个没有任何 `.razor.cs` 后置；9 个把
`@attribute [PageInfo/PageGroup/AllowAnonymous]` 也写在 razor 里；唯一有后置的是 `Dashboard.razor`。
⇒ 纯 C# 语法扫描方案命中率 0/17。

### 三条可选改造路线

- A. `AdditionalFiles Include="**/*.razor"` + `AdditionalTextsProvider` 文本解析 `@page`/`@attribute`/`@namespace`
     （复用仓库里 SvgContentClassGenerator 已有的套路）。业务页面零改动，但要写 mini razor 指令解析器。
- B. 把 `@page` 改成 `.razor.cs` 里的 `[Route]`，`@attribute` 改成真实特性。100% 等价、全保真，但要动 17 个文件。
- C. 混合：C# 语义树（全保真）+ razor 文本（兜底补 `@page`/`@attribute`）。推荐。

### ScanRazorLibraryAssembly 是另一个独立问题

```csharp
Assembly.GetEntryAssembly().GetReferencedAssemblies().Select(Assembly.Load)
item.ExportedTypes.Any(t => t.GetCustomAttribute<RouteAttribute>() != null)
```
- `GetReferencedAssemblies()` 裁剪后会少报；`ExportedTypes`+`GetCustomAttribute` 是运行时元数据反射，AOT 无法感知 → 页面类型会被裁掉。
- 正解不是"生成器扫描"，而是每个含页面的程序集自己生成注册代码：
  `[ModuleInitializer] static void RegisterPages() { AppConst.AddAssembly(typeof(页面)); RouteRegistry.Register(new RouteMeta{...}); }`
- ⚠️ 坑：`[ModuleInitializer]` 只在模块首次被访问时触发，主程序集必须显式触碰一次该程序集的某个类型。

### 用户决策（2026-09-03）：本次只留结论，不改代码

- **ScanRazorLibraryAssembly 的改造（Assembly.Load + ExportedTypes）：暂缓。**
- **路由元数据扫描（A 文本解析 / B 搬代码后置 / C 混合）：暂缓。**
- PagesService 的反射（`ExportedTypes` + `GetCustomAttribute<RouteAttribute>`）保持现状。
- 后续要动时，推荐从「C 混合方案 + 先做最小可跑 demo」切入。
