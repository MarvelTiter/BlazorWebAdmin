## PageRouteRegistryGenerator：入口程序集 vs 附加程序集登记

需求：生成器判断当前编译产出的程序集是不是应用入口程序集——
是则设置 `AppConst.AppAssembly`，否则调用 `AppConst.AddAssembly`（不要再调 AddAssembly）。

实现：
- `PageRouteContext` 新增 `RegisterAppAssembly(Type?)`：设置 `AppConst.AppAssembly = routeType.Assembly`，
  并把 assembly 记入 `RegisteredAssemblies`。原 `RegisterAssembly(Type?)` 语义收窄为"非入口程序集"，
  仍走 `AppConst.AddAssembly`。
- `PageRouteRegistryGenerator` 新增 `IsEntryAssembly(Compilation)`：
  `compilation.GetEntryPoint(CancellationToken.None) is not null` 为主判据，
  兜底 `compilation.Options.OutputKind is OutputKind.ConsoleApplication or OutputKind.WindowsApplication`。
  Emit 时按结果选择 `RegisterAppAssembly` / `RegisterAssembly`。

实证（`-p:EmitCompilerGeneratedFiles=true -p:CompilerGeneratedFilesOutputPath=obj/GF7`）：
- `BlazorTemplate.ClientCore`（类库）→ `RegisterAssembly(typeof(...BuildInPages.OnlineUsers))`
- `BlazorAdmin.Client`（WASM Exe）→ `RegisterAppAssembly(typeof(...TestPages.FormBuilderTest))`

结论/注意：
- 模块初始化器先于 `Main` 执行，随后 `Program.cs` 里的 `AppConst.AppAssembly = ...` 会覆盖成同一程序集，不冲突。
- 入口程序集若没有 `.cs` 里显式 `[Route]` 的类（页面全在 razor），生成器不产出代码，AppAssembly 仍由 Program.cs 设置，无回归。

## 环境坑（复现确认）

Bash 工具里 `APPDATA` 与 `ProgramData` 为空，NuGet 读配置时 `Path.Combine(null)` 直接抛
"NuGet 包路径为空" 类错误，与代码无关。构建前需：
```
export APPDATA='C:\Users\Marvel\AppData\Roaming'; export ProgramData='C:\ProgramData'
```
验证仍一律带 `--no-incremental`，否则 obj 缓存会给出假绿。
