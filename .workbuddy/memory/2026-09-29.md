# 2026-09-29

## FluentUI 自定义 svg 图标 viewBox 被 Icon.ToMarkup 固定问题修复

**现象**：`FluentIconClassGenerator` 生成的 `SvgXxxIcon : Icon` 传 `IconSize.Custom` + svg 的 `InnerContent`（`<g>` 内层），但 v5 `Icon.ToMarkup` 把 viewBox 固定为 `((int)Size)`，导致 svg 自身 viewBox 丢失，非正方形 svg 被拉成正方形。

**根因**（v5 `Icon.cs` 源码确认）：
- `Icon.ToMarkup(string? size, string? color, string? backgroundColor, string? slotName, string? role)` 返回 `MarkupString`，`virtual` 可重写。
- 第一分支（`Size != IconSize.Custom && ContainsSVG`）viewBox 写死 `0 0 {((int)Size)} {((int)Size)}`（正方形）。
- `ContainsSVG` 只认 `<path`/`<rect`/`<g`/`<circle`/`<mark` 开头，**不认 `<svg`**（完整 svg 文档）。
- `Icon.Content` 是 `virtual string Content { get; }`（只读自动属性，构造函数赋值）；`Icon.Width` 是 `protected internal virtual int Width`。
- 官方 `CustomIcon.cs` 只复制 `IconInfo`，未重写 `ToMarkup`，无现成「完整 svg viewBox」处理示例。

**修复**：生成器 `FluentIconClassGenerator` 让每个 `SvgXxxIcon` override `ToMarkup`：
- 从 `SvgFileParse` 的 `Attributes` 字典解析 `viewBox`/`width`/`height`。
- **宽高以 viewBox 为准**（`viewBox = "minX minY width height"`，取第 3/4 项），而非源文件 width/height 属性（svg-station.svg 源文件 `height="24px"` 但 viewBox 高 21，属性写错了）。
- 产物输出 `<svg viewBox="{svg的viewBox}" width=".." height=".." fill="{color|currentColor}" aria-hidden="true">` + `Content`。
- viewBox/width/height 存为 `private const string`，用 `ToLiteral` 转义（引号/反斜杠）。
- `fill` 用 `color ?? "currentColor"`（可上色，替代 svg 里硬编码的 `fill:rgb(0%,0%,0%)`）。

**关键点**：
- `MarkupString` 全限定名 `global::Microsoft.AspNetCore.Components.MarkupString`。
- 生成器 netstandard2.0，`ToLiteral` 里 `value!.Trim()` 需加 `!` 消除 CS8602（`IsNullOrWhiteSpace` 流分析不足）。
- 验证：svg-station（viewBox `0 0 24 21`）正确产出 `DefaultWidth="24" DefaultHeight="21"`。

## Icon.Size 是 init 不可改 → 引入中间基类 SvgIconBase + WithSize

**背景**：`IconInfo.Size` 是 `public virtual IconSize Size { get; init; }`（init 只能在构造/初始化器赋值）。`IconHelper.GetCustomIcon` 里 `size != IconSize.Custom` 时原用 `new Icon(name, variant, size, content)` 重建，**丢掉了 `SvgXxxIcon` 的 `ToMarkup` override**（新实例是基类 `Icon`，viewBox 又被固定成 `((int)Size)`）。

**方案**：生成器产物多继承一层抽象基类 `SvgIconBase : Icon`：
- 构造接收 `name, viewBox, defaultWidth, content, size`，`base(name, Regular, size, content)`。
- override `ToMarkup`：viewBox 用 `_viewBox`，width 跟随 `Size`（`Size==Custom ? _defaultWidth : (int)Size` px），**只设 width 不设 height**（height 靠 viewBox 宽高比自动，非正方形 svg 如 station 24×21 也能正确缩放）。
- `abstract Icon WithSize(IconSize size)`，每个 `SvgXxxIcon` override 返回 `new SvgXxxIcon(size)`。
- `IconHelper` 改：`size != Custom && generated is SvgIconBase b` → `b.WithSize(size)`。

**关键点**：
- `WithSize` 返回 `Icon`（基类类型），调用方 `FluentNavItem.IconRest` 等参数接收 `Icon`，无需改调用方。
- `init` 属性可在**派生类构造函数**里通过 `base(...)` 重新赋值，故 WithSize 用「新实例」而非「改属性」。
- 真实调用方 `FluentUIMenuItem.razor` 用 `GetCustomIcon(Route.Icon, size: IconSize.Size20)`（菜单图标 20px），是 size 不一致的唯一场景。

## 关键转折：重写 ToMarkup 对 FluentIcon 组件渲染【无效】

**决定性根因**：`FluentIcon.razor`（泛型组件）**根本不调用 `Icon.ToMarkup`**，它自己硬编码渲染：
```razor
@if (_icon.Size != IconSize.Custom && _icon.ContainsSVG)
{ <svg viewBox="0 0 {(int)_icon.Size} {(int)_icon.Size}">@_icon.Content</svg> }
else  // Size == Custom 走这里
{ <div>@_icon.Content</div> }
```
- `Size == Custom` → 走 `<div>` 分支，viewBox 全丢。
- `Size != Custom` → viewBox 写死正方形 `0 0 {Size} {Size}`，非正方形 svg 被拉伸。
- 所以**重写 `ToMarkup` 对 `<FluentIcon>` 渲染路径无效**（ToMarkup 只用于 ToDataUri 等字符串场景）。
- 这是官方**设计限制**（非 bug）：issue #1328「允许手动设置 SVG viewBox」+ #1124「解耦图标尺寸与 viewport」。官方唯一出路是 `IconSize.Custom` + `Content` 返回**完整 `<svg>` 文档**（含自己的 viewBox）。维护者 dvoituron 明确「Fluent 系统图标不同尺寸的 path 细节不同，故 viewBox 绑定 IconSize 是设计使然」。

## 最终方案（对齐官方 IconSize.Custom 语义）

**用户拍板**：自提供完整 svg 文档，基类**不再重写 ToMarkup**，`WithSize` 改为「直接改 svg 文档的 width/height 属性，再返回新 Icon 对象」。

**实现**：
- `SvgIconBase : Icon`：构造 `(name, svgContent, size)`，`base(name, Regular, size, svgContent)`；`abstract Icon WithSize(size)`；`protected static string Resize(string svgTemplate, IconSize size, string defaultWidth)` 用 `Replace("__W__"/"__H__", px)` 替换占位符。
- 生成器 `FluentIconClassGenerator`：`Content` 用 `r.OriginalContent`（完整 `<svg>` 文档，含 viewBox/width/height），用正则把 `<svg>` 开标签里的 `width="X"`/`height="Y"` 替换成 `__W__`/`__H__` 占位符存为 `SvgTemplate` const。
- 每个 `SvgXxxIcon : SvgIconBase`：构造 `base(name, Resize(SvgTemplate, size, defaultWidth), size)`；`WithSize(size) => new SvgXxxIcon(size)`。

**踩坑**：
- `Resize` 必须是 **static**（`base(...)` 调用里不能访问实例方法，C# 限制），故 `defaultWidth` 也作为参数传入。
- 正则替换 width/height 要防误匹配 `stroke-width`：用 `(\s)width="..."` 捕获前导空格。
- svg 内层是纯 `<path>`/`<g>`，无 CSS 花括号，占位符方案安全。
- `SvgIconBase.cs` 是**手写文件**（`Components/SvgIconBase.cs`），不在生成器里生成（与生成器产物解耦）。

## 多级字典管理（新增功能）

按既有「实体 + 泛型服务 + 页面」约定落地多级字典。审计（AuditLog）暂缓。

**新增文件**（`BlazorTemplate.ClientCore`）：
- `Models/Dictionary/IDictType.cs` — `IDictType` + `TemplateDictType`（`LightTable DICT_TYPE`）
- `Models/Dictionary/IDictItem.cs` — `IDictItem` + `TemplateDictItem`（`LightTable DICT_ITEM`，`ParentId` 多级树 + `Children` + `ItemLevel`）
- `Services/IDictionaryService.cs` — 泛型 `IDictionaryService<TDictType,TDictItem>` + `ITemplateDictionaryService`（`[WebController(Route="template/dict")]`）
- `DefaultServicesImpl/DefaultDictionaryService.cs` — 泛型默认实现（删类型/删项均走事务级联；删项递归删子孙）
- `DefaultServicesImpl/TemplateDictionaryService.cs` — 具体化 + `[AutoInject]` 注册
- `BuildInPages/DictTypePage.cs/.razor` + `DictItemPage.cs/.razor` — 两个页面（类型 CRUD + 树形字典项，顶部类型下拉联动）

**改动文件**：`ConstraintString`（加 `DICT_TYPE_URL`/`DICT_ITEM_URL`）、`IPageLocatorService`（加 Get/SetDictType/DictItemPageType）、`BuildInPages/PageIndex.cs`（加 `DictTypeIndex`/`DictItemIndex` 路由入口，GroupId 挂 "BasicSetting"）、`usings.cs`（加 `global using Models.Dictionary`）、`BlazorAdmin/Program.cs`（两处 ConfigurePage 绑定字典页面）。

**踩坑（可复用）**：
- razor 文件里 `@typeparam` 约束用到新命名空间类型时，需显式 `@using` 或加入 `usings.cs` global using——`Models.Dictionary` 未 global using 导致 CS0246+CS0265 连锁报错。
- `LabelExpression`/`VisibleExpression` 的委托签名是 `Func<TableButtonContext<TData>, string/bool>`，**不是** `Func<TData, ...>`（CS0123）。参照 `PermissionSetting.AddPowerLabel(TableButtonContext<TPermission> _)`。
- `context.CreateMainDbScoped()` 返回 `ISingleScopedExpressionContext`（LightORM），递归删树的方法参数类型要写它，不是 `IExpressionContext`（CS1503）。
- `TableButtonAttribute` **无 `Sort` 属性**；按钮顺序靠特性声明顺序/源生成器收集。

**验证**：`BlazorTemplate.ClientCore` 与 `BlazorAdmin` 均 0 错误构建通过。实体表由 `[LightORMTableContext]` 源生成器自动扫描注册，无需手动改 `LightOrmTableContext`。

**单表改造（用户拍板：字典表一个即可）**：
- 删 `IDictType`/`TemplateDictType`，合并为单表 `DICT_ITEM` 自关联无限级树——`ParentId` 为空 = 根节点（即「字典类型」，`ItemLevel=0`），其余为多级字典项。
- 实体字段收敛为：`ItemId`（主键）/`ItemKey`/`ItemValue`/`ParentId`/`Sort`/`ItemLevel`/`Children`，去掉 `DictTypeCode`。
- 服务接口 `IDictionaryService<TDictItem>` 去掉 `TDictType` 泛型参数，方法收敛为 `GetAllDictAsync`/`GetDictItemListAsync`/`Insert`/`Update`/`Delete`。
- 页面合并为单页 `DictPage`（树形，`OnAddItemAsync` 建根=类型，`AddChild` 建子项）。
- 路由收敛为单个 `DICT_URL="/dict/index"` + `DictIndex` + `GetDictPageType/SetDictPageType`。
- `BlazorAdmin/Program.cs` 两处绑定改为 `SetDictPageType<TemplateDictPage>()`。
- 验证：双项目 0 错误 0 警告。
