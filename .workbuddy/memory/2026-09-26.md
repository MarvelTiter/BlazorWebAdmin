## FluentUI 图标抽象收口（UI 抽象层治理）

**背景**：`IUIService` 按 AntDesign 实现基准，图标用 `string`（`IconInfo.Name`）+ `MIcon`（模板内置 svg/font 图标组件）。FluentUI 的图标是编译期强类型 `Icon` 类（`FluentIcon<TIcon>`，`TIcon : Icon`），不能嵌入 `MIcon`，导致 `RenderIcon` 长期 `NotImplementedException`。

**根因**：`MIcon` 是「运行期字符串 + 动态查 svg」，FluentUI 是「强类型 `Icon` 对象 + SVG 内容内嵌」。桥接点是已存在的 `IconHelper.GetCustomIcon`（字符串 → `new Icon(name, variant, size, svgContent)`），但方向没走完：写成 `async Task` + `StateHasChanged` 二次渲染，且 `RenderIcon` 没接上。

**改动**（3 处）：
1. `IconHelper.GetCustomIcon` 改同步（`ISvgIconService.GetIcon` 本就是同步），`GetOrAdd` 缓存。
2. `FluentUI/UIService.cs` 的 `RenderIcon` 补全：`svgIconService.GetCustomIcon` → `Component<FluentIcon<Icon>>().SetComponent(i => i.Value, fluentIcon)`。`ISvgIconService` 通过**构造函数注入**（不是 `GetRequiredService<T>`）。
3. `FluentUIMenuItem.razor` 去掉异步 `GetCustomIcon` + `StateHasChanged`，改同步 `OnInitialized`。

**关键坑（CS8920，务必记住）**：`ISvgIconService` 含 `abstract static RegisterIcons<T>()` 静态抽象成员，**该接口类型不能作为泛型实参**。所以 `GetRequiredService<ISvgIconService>()`（`TService=ISvgIconService`）直接 CS8920 编译失败。修法：用构造函数注入（非泛型参数），不用泛型 `GetRequiredService<T>`。

验证：`BlazorTemplate.UI.FluentUI` net10.0 编译通过，0 错误（剩余警告为 FluentTable/EnumValues 等既有问题，无关本次改动）。

**下一步（未做）**：`BuildMenu(router, horizontal, app)` 签名仍 Ant 化（`horizontal` 是 Ant 折叠语义），Fluent 侧还有多个 `NotImplementedException`（BuildDynamicTable/BuildForm/BuildDropdown/BuildTree/BuildRow/Col/Tabs 等）待逐个补形态映射。
