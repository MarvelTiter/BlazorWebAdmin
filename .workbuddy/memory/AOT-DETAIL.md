## R2 修法：`MakeGenericMethod` → 方法组委托 + `Expression.Invoke`
典型场景：表达式树要调 `Enumerable.ToList<TValue>()`，原走
`typeof(Enumerable).GetMethod("ToList")!` + `MakeGenericMethod(typeof(TValue))` + `Expression.Call`。
`TValue` 在本封闭泛型类型里**静态可见** ⇒ 直接方法组转委托：

```csharp
private static readonly Func<IEnumerable<TValue>, List<TValue>> toList = Enumerable.ToList;
// 表达式树侧： Expression.Invoke(Expression.Constant(toList), source)
```

实例化点由编译器写死在本类型内，一举消掉 IL3050 + IL2060，并干掉字符串 `GetMethod`
（原靠 `!` 压 null，裁剪下有 NRE 隐患）。已落地 `UI/Builders/SelectComponentBuilder.cs`
（2026-09-19 双 TFM 全量构建 0 错误，`IL2060` / `SelectComponentBuilder` 0 命中）。

## 生成产物自身的硬约束（踩过坑）
- **文件头必须显式写 `#nullable enable`**。自动生成文件**不继承**项目级可空上下文，产物里出现 `string?`
  而头部只有 `// <auto-generated />`，编译器会对**每个** `string?` 报一条 CS8669。
- 产物里**不要用字符串插值拼 C# 字符串字面量**（标签含 `"` 会产出断码），统一走
  `SymbolDisplay.FormatLiteral(value, quote: true)`。
- 类名 / hintName 要唯一化：同名枚举分布在不同命名空间会撞名。用**稳定哈希**（FNV-1a），不要用
  `string.GetHashCode()`——跨进程不稳定。
- 多语法源合流（"当前编译单元的枚举声明" + "`AddEnumLookupProvider<T>()` 泛型实参"）必须**按全名去重**，
  否则同一个符号提交两份 `AddSource` 直接抛异常。
- 暴露 `Type` 常量优于暴露名字字符串：`typeof(TEnum)` 在 AOT 下安全，且不怕简单名冲突。键用 `Type`、
  值域用 `Array` / `object` + 拆箱，可完全绕开 `MakeGenericMethod`。
- 产物要在**消费方项目**里编译，而本仓库是模板仓库、消费方 `LangVersion` 不可控 ⇒ 语法取最保守形式：
  显式 `new Xxx(...)`，**不用集合表达式 `[...]`、不用目标类型 `new()`**。

## 类型擦除 vs 泛型的分界（EnumHelper 一案）
"按运行时 `Type` 查表 + 泛型化" 二者**不可兼得**：要拿到 `IXxx<TEnum>` 只能 `MakeGenericType`
（= R2 硬阻塞），或者给 `TEnum` 加约束（则 `TEnum?` 这类可空实参全断）。
⇒ 规则：**注册表/查表层保持类型擦除（`object`/`Array`），泛型只出现在实参可静态写死的地方。**
`EnumHelper<TEnum>` 因 `FluentEnumSelect<TEnum>` 的 `[Parameter] TEnum? EnumValue` 必须**无约束**，
所以 `IEnumMeta` 刻意非泛型；泛型只用在 `EnumLookupProvider<TEnum>`（生成代码写死具体枚举名）。

推论：**能靠"通用类 + 元数据"做的事，不要逐符号生成类**。枚举下拉原本逐枚举生成
`{X}LookupProvider`，其职责只是"元数据 → `LookupEntry`"、与具体枚举无关 ⇒ 收敛成一个
`EnumLookupProvider<TEnum>` 适配器，生成器只产元数据。

枚举 / 查找相关命名空间是 `BlazorTemplate.ClientCore.Lookup`（目录 `Lookup/`，2026-09-19 由 `Lockup/`
改名）。生成器模板里写死的 `using` 不走 IDE 重命名，**重命名这类目录后务必检查生成器模板里的字符串字面量**。

## AOT 注解事实（实测，勿凭印象）
- `Expression<TDelegate>.Compile()`：**无** `[RequiresDynamicCode]`；基类 `LambdaExpression.Compile()` 才有。
- `Enum.TryParse(Type, string, out object)`：**无**注解，AOT 安全（名字/数字/`Flags` 语义都保留）。
  泛型形式 `Enum.TryParse<TEnum>(string, out TEnum)` 亦是编译期实例化，**AOT 安全**。
- `Enum.GetValues(Type)` / `Enum.GetName(Type, object)` / `GetField().GetCustomAttribute<T>()`：
  分别报 IL3050 / IL2075，是 `EnumHelper` 原本的问题源（**2026-09-18 已由 `IEnumMeta` 源生成器消除**）。
- `ServiceCollection.AddScoped<TService, TImplementation>()` 的 `TImplementation` 带
  `DynamicallyAccessedMemberTypes.PublicConstructors`，泛型方法转发时会报 IL2091
  （`LookupServiceBuilder.cs:10,16` 即此），修法是给泛型参数补 `[DynamicallyAccessedMembers]`。
- **`RenderTreeBuilder.OpenComponent<TComponent>()` 要求 `TComponent` 带 DAM `All`**，否则报 IL2091
  （`ComponentBuilderBasic.cs:89`、`ComponentBuilder.cs:50` 即此）。为何要 `All` 而不是只 `PublicProperties`：
  `UI/Builders` 这层**完全靠 `AddMultipleAttributes(Dictionary<string,object>)` 按字符串名匹配
  `[Parameter]`**，是反射式属性赋值，裁剪器必须保住组件类的全部成员。修法会**沿继承链级联**
  （`ComponentBuilderBasic` → `ComponentBuilder` / `PropComponentBuilder` / `BindableComponentBuilder` /
  `SelectComponentBuilder` / `ButtonComponentBuilder` / `CustomComponentBuilder` → 各 UI `UIService` 构造点）。
- `ServiceCollection.ConfigureOptions<T>` 需 DAM `All`。
- `MemberInfo.GetCustomAttribute<T>()`（`T` 是编译期已知的具体特性类型）**不告警**——
  裁剪器视为该特性已保留。只有 `Type` / 字符串反射那一类才报 IL2075。
- `Expression.Property(expr, PropertyInfo)` **安全**（`prop.DeclaringType` 允许是 `expr.Type` 的基类）；
  只有 `Expression.Property(expr, string)` 重载报 IL2026。

## DAM 标注的两条铁律（2026-09-24 落地验证）
1. **开放泛型基类 / 扩展方法【不】标 DAM，用局部 `[UnconditionalSuppressMessage("Trimming","IL2091")]`。**
   判据：泛型参数实参是**封闭具体类型**（Builder 的组件类型、`InvokeAsync<T>` 的 DTO）→ 标 DAM；
   实参**可被消费方任意扩展**（`ModelPage<TModel>` 的 `TModel`、`DialogTemplate` 派生、`AddTab<T>`）→
   标 DAM 会无边界级联到所有继承者（实测 ModelPage 标 All 后 5 个派生页 + 5 个扩展方法全报新 IL2091）。
2. **DAM 只能加在泛型参数 `<T>` 位置，不能加在方法返回类型位置**（`[DAM] T Foo<[DAM] T>()` 的返回值
   位置非法，CS1031 等一堆错）；返回值 DAM 由泛型参数自动推导。
   已落地：Builder 链 7 个类 `TComponent` 标 All、`InvokeAsync<TValue>` 标
   `PublicConstructors|PublicFields|PublicProperties`、`ConfigureOptions<T>` 标 All、
   `ModelPage` / `DialogExtensions` / `AddTab` 局部压制。
   结果：IL2091 去重站点从 ~49 → 1（仅剩 `DefaultCopyService` 的 `GMapper.Map<T,T>`，跨仓库）。

## Lookup 加载路径（当前设计：provider 自驱）

**硬约束（不变）**：读接口（`GetDisplayString` / `GetEntries`）的消费方全在渲染路径上
（`AntTable.razor.cs:124`、`InputBuilder.cs:77`、`Condition.razor.cs:85`、`Group` / `SingleConditionBuilder`），
无法 `await` ⇒ 它们**只读缓存、绝不触发加载**。

2026-09-30 用户**自行回退了「宿主 await 预热」的异步化改造**，改为 **provider 自驱加载 + `category` 参数重载**。当前形态：

| 类型 | 形态 |
|---|---|
| `ILookupProvider` | `TypeName` + `GetDisplayString(key)` / `GetDisplayString(category, key)` / `GetEntries()` / `GetEntries(category)` |
| `ILookupService` | `GetDisplayString(type, key)` / `GetDisplayString(type, category, key)` / `GetEntries(type)` / `GetEntries(type, category)` |
| `LookupService` | `Build()` 把静态枚举表 + 作用域内 DI provider 合成 FrozenDictionary；`AddEnumProvider` 静态注册；category 版透传给 provider |
| `EnumLookupProvider<TEnum>` | 纯数据适配器，构造期由 `IEnumMeta` 填 `FrozenDictionary` |
| `BaseLookupProvider` | `ILookupProvider + IAsyncDisposable`；缓存为 `FrozenDictionary<category, FrozenDictionary<code, LookupEntry>>`；**构造函数**启 `RefreshInterval` 轮询循环自驱；`LoadMultiplyDataAsync`（virtual，默认包一层 `DEFAULT_CATEGORY`）+ `BuildDictionary`（virtual）；`LoadAsync` / `ReloadAsync` 为 **private** |
| `DictionaryLookupProvider<TDictItem>` | `TypeName => DICTIONARY_LOOKUPTYPE`（固定常量）、`category = TypeCode` ⇒ **一个 provider 服务所有字典类型**；`RefreshInterval = 2min` |

**`category` 方案的意义**：TypeName 固定 ⇒ 无需「未命中动态源」那套路由（我原方案 1），直接在
`lookups` 表里注册一个 provider，用 `category` 区分组内维度。代价是消费端必须能传 category —— 而
`ColumnInfo` / 5 个消费点目前都走无 category 重载，**新重载尚无调用方**（见下）。

**踩坑（实测）——`new Task(async () => {...}, TaskCreationOptions.LongRunning)` 永不执行**：
`Task` 的**构造函数**创建的是**冷任务**，不 `Start()` 就一直停在 `Created`。实测探针
（`.workbuddy/tmp/taskprobe/`）复刻该写法：循环体从未进入，`Status = Created`。
换成 `Task.Factory.StartNew(Func<Task>, TaskCreationOptions.LongRunning)`（用户当前写法）后循环能跑，
但**不 `Unwrap()` 时返回 `Task<Task>`**：外层在第一个 `await` 处即完成 ⇒ 实测 `loadTask.Status =
RanToCompletion`（此时 loads 仍在增长），`await loadTask` / `loadTask.Dispose()` 都不代表循环已结束。
另：`async` lambda 绑定到 `Task(Action)` 重载 = **async void** ⇒ 异常直接崩进程。

**循环体必须整体包 try/catch（实测）**：异常存进内层 Task 且无人观察 ⇒ **循环永久静默终止**。
实测注入一次异常后计数停止增长、恢复后不再继续、进程无任何输出。

其他待收敛点：`BuildDictionary` 只取 `datas.FirstOrDefault()` ⇒ 多 category 只有第一个存活；
`DEFAULT_CATEGORY` 是 private const，派生类引用不到；`defaultCategory ??= cache!...` 只在 null 时赋值
⇒ 首次命中后被永久冻结，`ReloadAsync` 换 `cache` 也不更新；`LoadDataAsync`(abstract) 与
`LoadMultiplyDataAsync`(virtual) 双扩展点 ⇒ 走多 category 的派生类仍被迫写
`throw new NotImplementedException()`；`GetEntries()` 无 category = 全 category 并集；
无可 `await` 的首轮完成信号 ⇒ 首帧仍可能读到空缓存（原 `InitializeAsync` 的作用），可暴露 `Task Warmup`；
`ILookupService.cs` 顶部 `using System.Collections.Frozen;` 已无用；`BaseLookupProvider.cs` 有无用
using（自引用命名空间、`System.Text`、`using static ...JavaScript.JSType`）。


已回退的历史结论（若重做「可强制刷新」时仍有效）：`Changed` 通知必须放在失败捕获的 try **之外**
（否则订阅方异常会被误记成加载失败）；后台刷新不能直接 `_ = RefreshAsync(type)`——HTTP 超时抛的
`TaskCanceledException` 属 `OperationCanceledException`，会逃出异常过滤器变成未观察的 Task 异常。

**注意**：provider 自驱 + `LoadAsync` 私有化 ⇒ 宿主机**无法强制刷新**，字典数据改完只能等
`RefreshInterval` 到期才生效（或重建作用域）。

## 设计结论：字典表**不**做「枚举 ⇄ 字典表」转换
结论：**不做双向转换。让字典表实现 `ILookupProvider` 并入现有 `LookupService`，枚举与字典互不转换。**

理由：
1. **双源冲突**：落库后 `IEnumMeta`（编译期）与 `DICT_ITEM` 谁是权威没法定，改显示名要改两处。
2. 丢掉枚举全部价值：`FluentEnumSelect<TEnum>`、`switch` 穷尽、`Enum.TryParse` 都不再可靠。
3. **AOT**：按运行时 `Type` 取回枚举 = `MakeGenericType` = R2 硬阻塞。只能返回 `object`（擦除），
   或让泛型实参由调用方静态写死。
4. `ColumnInfo.LookupType` 是**可写**属性（getter 默认 `IsEnum ? 类型名 : null`），列上给个字符串就能切到
   任意 provider；`DICT_ITEM(TypeCode/ItemValue/ItemName)` 与枚举同构（都是 code→name）。

落地建议（若要推进）：A（主路径）加 `DictionaryLookupProvider : ILookupProvider`（`TypeName = TypeCode`，
数据来自 `IDictionaryService`）；B（若要强类型）只加**单向** `GetEnumAsync<TEnum>`，内部用泛型
`Enum.TryParse<TEnum>`；C（若要枚举当初始数据）只做一次性种子 upsert，**不做运行时双向同步**。
