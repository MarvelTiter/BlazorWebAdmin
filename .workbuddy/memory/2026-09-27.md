## FluentUI 侧 svg→强类型 Icon 生成器（方案 1+3 落地）

**目标**：解决「项目自定义 svg 图标（字符串驱动）与 FluentUI 强类型 `Icon`」的阻抗失配。

**关键决策链（几轮讨论的结论）**：
1. `Icon.FromImageUrl`（方案 2+3）被否——它是 `<img>` 渲染，**失去 fill 上色能力**（官方 Issue #1240「IconColor has no effect when loading Icon from SVG in FluentNavLink」、#3032 对齐问题、#5228 closed:not-actionable）。项目 svg 图标靠 `fill:currentColor` 内联上色，不能走 img。
2. 正解是「继承 `Icon` 类 + 构造函数内嵌 svg 内容」（官方 Customization 的 `MyCircle` 示例路线），即**方案 1+3**。

**落地**：
- 新建独立生成器项目 `BlazorTemplate.UI.FluentUI.Generators`（netstandard2.0），含 `FluentIconClassGenerator.cs`。
- 生成器扫 `AdditionalTextsProvider` 里的 `svg-*.svg`，为每个生成 `SvgXxxIcon : Icon`（`IconVariant.Regular` + `IconSize.Custom` + svg raw string literal 内嵌），并额外生成 `FluentIcons.Get(string name)` 编译期 switch 分发（零运行时反射）。
- `FluentUI.csproj` 增加 `AdditionalFiles Include="..\BlazorTemplate.ClientCore\wwwroot\icons\*.svg"`（跨项目引用 ClientCore 的 svg）+ 挂载新生成器。
- `IconHelper.GetCustomIcon` 改为：先 `FluentIcons.Get(name)`（命中生成类直接返回），未命中回退运行时 `new Icon(...)`（保留兜底）。
- 产物命名空间 = 编译程序集名（`BlazorTemplate.UI.FluentUI`），`IconHelper` 在 `...Components` 子命名空间，靠父命名空间可见性直接访问，无需 using。

**踩坑（重要，务必记住）**：
1. **生成器不能放在 `BlazorTemplate.ClientCore.Generators` 项目里**——ClientCore 也挂了这个生成器程序集（为了 `SvgContentClassGenerator`），新生成器会被 ClientCore 跑一遍，而 ClientCore 不引用 FluentUI → CS0234「命名空间 Microsoft 中不存在 FluentUI」。**每个库专属的生成器必须独立成项目**，只挂到引用该库的项目。
2. 生成器是 netstandard2.0 不得引用宿主类型（FluentUI `Icon`），产物里 FluentUI 类型全用 `global::Microsoft.FluentUI.AspNetCore.Components.Xxx` 字符串全限定名。
3. `#nullable enable` 文件头必写（auto-generated 文件不继承项目可空上下文）。

**验证**：FluentUI net10.0 编译 0 错误；`EmitCompilerGeneratedFiles` 落盘检查产物正确（28 个图标，raw string literal 内嵌 svg 无误，switch 分发完整）。

**遗留**：FluentUI 侧仍有多个 `NotImplementedException` 待补（BuildDynamicTable/BuildForm/BuildDropdown/BuildTree/BuildRow/Col/Tabs 等），`BuildMenu(router,horizontal,app)` 签名仍 Ant 化。

## FluentUI 第 1 档 NotImplementedException 补齐（直接映射）

`BuildMenu(router,horizontal,app)` 签名**不改**——`horizontal` 是框架语义（传给实现层，实现层用不用是自己的事）。

**已补（第 1 档，直接映射）**：
| 方法 | 映射 | 形式 |
|---|---|---|
| `BuildRow` | `FluentGrid` | `PropComponentBuilder` 直接映射 |
| `BuildCol` | `FluentGridItem`（`ColSpan` → `xs` 断点） | `PropComponentBuilder` |
| `BuildTabs` | `FluentTabs` + `FluentTab`（`Label`/`Header`/`ChildContent`） | `PropComponentBuilder` |
| `BuildDropdown` | `FluentMenuButton`（`ButtonContent`=触发、`ChildContent`=`FluentMenuItem`） | 新适配组件 `FluentDropdown.razor` |
| `BuildProfile` | `FluentPopover`（用户信息 + 修改密码/退出） | 新适配组件 `FluentProfile.razor` |
| `BuildPopover` | `FluentPopover`（AnchorId 锚定 + Open 状态管理） | 新适配组件 `FluentPopoverHost.razor` |

**踩坑**：
1. **适配组件不能与 FluentUI 官方组件同名**——`FluentPopover` 撞了官方 `Microsoft.FluentUI.AspNetCore.Components.FluentPopover`，CS0104 歧义。改名 `FluentPopoverHost`。同理要注意 `FluentTable`/`FluentLogin` 等已存在的适配组件名是否与官方冲突（当前没冲突，官方是 `FluentDataGrid` 等）。
2. FluentUI 的 `FluentPopover` 与 Ant 的 `Popover` 语义差异大：FluentUI 要 `AnchorId` + 手动 `Open`/`OpenChanged` 状态管理（无 Ant 的 Trigger 自动弹出），需适配组件包一层。
3. `FluentMenuButton` 子内容必须显式声明 `ButtonContent`（触发内容）和 `ChildContent`（菜单项），不能平铺。

**验证**：FluentUI net10.0 编译 0 错误。

**仍遗留（第 2 档，需自定义包装组件）**：`BuildDynamicTable`、`BuildForm(FormOptions)`、`BuildTree`、`BuildCheckBoxGroup`、`BuildRadioGroup`——FluentUI 无直接等价物，需像 `FluentTable` 那样写适配组件。

## FluentUI 4.14.4 → 5.0.0 迁移（大版本，Critical 级）

v5 是 Critical 级重构（底层 FAST → Fluent UI Web Components v3）。官方迁移指南标 **Dialog、Select、List 三个 Critical**。

### 已完成的低风险机械替换（用户说 Dialog 自己处理，我只做低风险）

| v4 | v5 | 涉及 |
|---|---|---|
| `IToastService` | `INotificationService`，`ShowSuccess`→`ShowSuccessToastAsync` 等（异步） | UIService、FluentTable |
| `FluentTextField` | `FluentTextInput`（`TextFieldType`→`TextInputType`） | UIService.BuildInput/BuildPassword、FluentLogin |
| `FluentNumberField<T>` | `FluentNumberInput<T>` | UIService.BuildNumberInput |
| `Appearance.Accent`/`.Neutral` | `ButtonAppearance.Primary`/`.Default` | UIService.BuildButton、FluentLogin、FluentProfile |
| `FluentToastProvider`×5 | `FluentProviders`（一个组件合并全部） | UIService.RenderContainer |
| `FluentDatePicker`（非泛型） | `FluentDatePicker<DateTime?>`（泛型） | UIService.BuildDatePicker |
| `Align.Center` | `DataGridCellAlignment.Center` | FluentTable |
| `FluentSelect<T>` | `FluentSelect<TOption,TValue>`（2 泛型），`SelectedOption`→`Value`，`OptionValue` 返回 `TValue?` | FluentEnumSelect/FluentTypedSelect |

### Select 泛型迁移的关键结论（重要）

- v5 `FluentSelect<TOption,TValue>`：`TOption`=选项类型、`TValue`=绑定值类型。`Value`/`ValueChanged` 来自 `InputBase<TValue>`（标准 Blazor 绑定），**选中项变更由 `FluentListBase` 内部自动调 `ValueChanged.InvokeAsync(GetOptionValue(...))`**，派生类**不要**自己重写 `OnChangeHandlerAsync`。
- `OptionText: Func<TOption?, string>?`、`OptionValue: Func<TOption?, TValue?>?`。
- **所有 Fluent 组件构造函数强制要求 `LibraryConfiguration` 参数**（v5 新增）。派生类写法：`public FluentEnumSelect(LibraryConfiguration configuration) : base(configuration) {}`（构造函数注入，`AddFluentUIComponents` 已注册到 DI）。**`LibraryConfiguration.Empty` 在 5.0.0 正式版 DLL 里不存在**（XML 文档是 RC 残留，CS0117），勿用。
- 枚举绑定 `FluentEnumSelect<TEnum>` → `FluentSelect<TEnum,TEnum>`，`OptionValue = e => e!` 直接返回枚举本身，**不再需要 string 中转**（v4 靠 `SelectedOption` string 反查）。

### 尚未处理（用户自己处理 Dialog；Popover 待确认）

- **Dialog**（UIService.cs:121/129/167、FluentTable.razor:120）：`DialogParameters`→`DialogOptions`（Header/Footer 子对象）、`ShowConfirmationAsync` 参数顺序变（v4 `(message,okText,cancelText,title)` → v5 `(message,title,primaryButton,secondaryButton)`）、`ShowSuccess`→`ShowSuccessAsync`。**用户明确说这部分自己来，我没动**。
- **Popover slot + Open 改名**（`FluentPopoverHost.razor`、`FluentProfile.razor`，RZ10012 警告级隐性 break）：v5 `FluentPopover` 的 `<Header>`/`<Body>` slot **全没了**（只剩 `ChildContent`），且 `Open`/`OpenChanged` **改名 `Opened`/`OpenedChanged`**。这是 Critical 级变化，运行时 popover 会失效，**待与用户确认是否也自己处理**。

## 弹窗架构重构：去 DialogTemplate + IDialogContent 接口（v5 Dialog 一并落地）

**用户诉求**：去掉 `DialogTemplate`（那个 `JsComponentBase`+`ICopyable`+`IStringLocalizer`+`Activator.CreateInstance` 职责混杂的桥接），改为**业务弹窗组件只实现 `IDialogContent<TReturn>` 接口**（`OnOkAsync`/`OnCancelAsync`/`ReturnValue`），`UIService` 内部用各自组件库的弹窗基类包装。

### 共享层（ClientCore）改动
- `FlyoutOptions` 泛型改为**双泛型 `FlyoutOptions<TInput, TReturn>`**（入参 `TInput` + 出参 `TReturn`）。内容组件类型**不进 FlyoutOptions 泛型**，由 `IUIService.ShowDialogAsync<TContent,TInput,TReturn>` 的**方法泛型 `TContent`** 承载。
- 删除 `IFeedback<TValue>`、`FlyoutOptions<TReturn>`、`FlyoutOptions<Template,TReturn>` 旧泛型。`PostCheckAsync` 签名改为 `Func<TReturn?, Func<bool>, Task<bool>>`（保留「传当前返回值 + 基础校验委托」语义，因 TestStackPanel 用了 `val`）。
- 新增接口 `IDialogContent<TReturn>`（`OnOkAsync()→Task<bool>` 返回 true 才关闭、`OnCancelAsync()`、`ReturnValue`），放 ClientCore 共享。
- 新增**薄基类 `DialogContentBase<TInput,TReturn>`**（继承 `AppComponentBase` 拿 UI/App/Router，提供 `Value`/`Edit`/`Options` 便捷访问 + 接口默认实现），**替代 DialogTemplate**，去掉了 JsComponentBase/ICopyable/深拷贝/CreateInstance。
- 新增 `RenderFragmentDialog<TData>` / `RenderFragmentDialog<TInput,TReturn>`（包装 RenderFragment content 场景）。
- 业务组件 `JsonDisplay`/`ModifyUserPassword`/`FormDialogTemplate`/`DrawerTemplate` 从 `@inherits DialogTemplate<T>` 改为 `@inherits DialogContentBase<T>`。
- 扩展方法（DialogExtensions/BuildFormExtension/DrawerExtensions/ModelPageExtension）改调新 API。`ModelPageExtension` 里 `FlyoutOptions<TModel>` → `FlyoutOptions<TModel,TModel>`。
- `IUIService.ShowDialogAsync<TContent,TInput,TReturn> where TContent : IComponent, IDialogContent<TReturn>`；`ShowDrawerAsync<TContent,...> where TContent : IComponent`（抽屉不强制 IDialogContent，`WebSetting` 是纯展示）。

### Ant 侧（ModalOptions.Content 是 RenderFragment，不需继承弹窗基类）
- `ShowDialogAsync` 用 `CascadingValue<FormParam<TInput>>` + `Component<TContent>()` + `AddComponentReferenceCapture` 拿 `IDialogContent<TReturn>` 实例（holder），`OnOk`/`OnCancel` 回调调 `contentRef.OnOkAsync()`/`OnCancelAsync()`。
- 关键：**`ref` 参数不能进 lambda**（CS1628），用 holder 对象（闭包捕获局部变量）代替 ref 传引用。

### FluentUI 侧（v5 Dialog，最复杂）
- **v5 弹窗 API 关键事实**（实测/源码确认）：
  - `IDialogService.ShowDialogAsync<TDialog>(DialogOptions)` / `ShowDialogAsync<TDialog>(Action<DialogOptions>)` **直接返回 `Task<DialogResult>`**（不是 `IDialogReference`）。
  - `TDialog : ComponentBase`，泛型参数标 `[DynamicallyAccessedMembers(All)]`。
  - `DialogResult`（非泛型）：`#ctor(object data, bool cancelled)` + `Cancelled` 属性 + **`GetValue<T>()`** 拿数据（**没有 `Data` 属性**）。
  - 关闭靠 footer 按钮 `DialogOptionsFooterAction.OnClickAsync`（`Func<IDialogInstance, Task>`）里 `instance.CloseAsync(result)` / `instance.CancelAsync()`。
  - `DialogOptions` 成员：`Header.Title`、`Footer.PrimaryAction/SecondaryAction`（`Label`+`OnClickAsync`+`Visible`+`Appearance`+`ShortCut`）、`Parameters`（`IDictionary<string,object?>` 注入 `[Parameter]`）、`Width`、`IsDrawer`、`PreventDismissOnEscape`、`Modal`。
  - **`DialogOptionsFooterAction.ToDisplay` 是 internal**（XML 有但 `<summary/>` 空，编译 CS1061），隐藏 footer 按钮用公开的 `Visible = false`。
  - 内容组件通过 `FluentDialog.RenderDynamicComponent(instance.ComponentType, instance.Options.Parameters)` 渲染，参数从 `DialogOptions.Parameters` 注入。
- 新增**包装组件 `FluentDialogContent<TContent,TInput,TReturn>`**（`ComponentBase`，非继承 FluentDialog）：内部 `CascadingValue<FormParam<TInput>>` + `Component<TContent>()` + `AddComponentReferenceCapture` 把实例写进 `DialogContentHolder<TReturn>`。footer 的 `OnClickAsync` 从 holder 读实例调 `OnOkAsync`/`OnCancelAsync`，再 `instance.CloseAsync(ReturnValue)`/`CancelAsync()`。
- 新增 `FluentDrawerContent<TContent>`（抽屉纯展示包装，不注入 FormParam）。
- 删除空壳 `FluentDialogWrap.razor`（`@inherits FluentDialogInstance`，v5 已无此基类）。
- `ShowConfirmationAsync` 参数顺序：v5 `(message, title, okText, cancelText)`，返回 `Task<DialogResult>`（不再是 `IDialogReference` + `.Result`）。
- **v5 声明式对话框（`BuildModal`/`MModal`）API 重构未完成**：`FluentDialog` 无 `Hidden`/`Visible` 布尔参数，改用 `Instance`+`ShowAsync`/`HideAsync`，`ModalProp.Visible/VisibleChanged` 桥接留待后续（当前 `BuildModal` 只映射 `ChildContent`，`MModal` 的 Visible 暂失效）。
- **本轮顺带修的 v5 第 1 档遗留 API 名错误**：`FluentGridItem.xs`→`Xs`（大写，`Xs`/`Sm`/`Md`/`Lg`/`Xl`/`Xxl`）、`FluentTab.Label`→`Header`（`Header`=纯文本、`HeaderTemplate`=富内容，无 `Label`）。

### 验证
ClientCore + AntBlazor + FluentUI 三项目双 TFM 全部编译 0 错误。

### 遗留
1. FluentUI `BuildModal`/`MModal` 声明式对话框的 `Visible/VisibleChanged` → v5 `FluentDialog.Instance` + `ShowAsync/HideAsync` 桥接未做（`MModal` 被 DefaultTableHeader/IconSelector 用到）。
2. Popover slot + `Open→Opened` 迁移（`FluentPopoverHost`/`FluentProfile`）未做（RZ10012 隐性 break）。
3. 深拷贝（`ICopyable.Copy`）从 DialogTemplate 下沉到 UIService 的逻辑**尚未落地**（Ant 侧 `PrepareInput` 里留了空注释，FluentUI 侧没做），`CopyValue` 语义暂缺。
4. `BuildDynamicTable`/`BuildForm`/`BuildTree`/`BuildCheckBoxGroup`/`BuildRadioGroup` 第 2 档适配组件仍 `NotImplementedException`。
