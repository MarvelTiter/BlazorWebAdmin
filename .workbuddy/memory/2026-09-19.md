## ComponentBuilder 抽象层的 AOT 检测结果

范围：`UI/Builders/*` + 其实现的接口 + 依赖的表达式工具 `Common/ExpressionHelper.cs`。
构建：`dotnet build ClientCore --no-incremental`（双 TFM），0 错误 / 175 条去重告警，抽象层命中 **5 处、3 类**。

### R2 真硬阻塞（1 处）

`UI/Builders/SelectComponentBuilder.cs:94,110` —— `ToArrayMethod.MakeGenericMethod(typeof(TValue))` /
`ToListMethod.MakeGenericMethod(typeof(TValue))`，同时报 **IL3050 + IL2060**。原话：
"'TComponent'…'MethodInfo.MakeGenericMethod(params Type[])' can not be statically analyzed…
The native code for this instantiation might not be available at runtime"。
配套的 `:86-87` 是 `typeof(Enumerable).GetMethod("ToList"/"ToArray")` 字符串反射（**分析器未告警**，
因为 BCL 类型不会被裁；但同一处 `!` 抑制了 null，属隐患）。
修法：换成**编译期封闭的静态委托**，用 `Expression.Invoke(Expression.Constant(del), source)` 代替
`Expression.Call(methodInfo, source)`；`Enumerable.ToArray`/`ToList` 的方法组可隐式转成
`Func<IEnumerable<TValue>, TValue[]>` / `Func<IEnumerable<TValue>, List<TValue>>`。
一次性把 `MakeGenericMethod` + 字符串 `GetMethod` 全干掉。

### ⚠️ IL2091（2 处，抽象层特有，之前没记过）

`UI/Builders/ComponentBuilderBasic.cs:89` 与 `UI/Builders/ComponentBuilder.cs:50` ——
`builder.OpenComponent<TComponent>(0)`。原话：
"'TComponent' generic argument does not satisfy 'DynamicallyAccessedMemberTypes.All' in
'RenderTreeBuilder.OpenComponent<TComponent>(Int32)'"。

**这不是噪声**：`RenderTreeBuilder.OpenComponent<TComponent>()` 要求组件类型带 DAM `All`，
因为这层抽象**完全靠 `AddMultipleAttributes(IEnumerable<KeyValuePair<string,object>>)` 按字符串名
匹配 `[Parameter]`**（走 Blazor 内部的反射式属性赋值）。裁剪器必须知道"组件类的所有成员都要保留"。
修法是给构建器继承链上的 `TComponent` 补
`[DynamicallyAccessedMembers(DynamicallyAccessedMemberTypes.All)]`——但会**级联**：
`ComponentBuilderBasic<TComponent,TSelf>` → `ComponentBuilder` / `PropComponentBuilder` /
`BindableComponentBuilder` / `SelectComponentBuilder` / `ButtonComponentBuilder` / `CustomComponentBuilder`，
再到 FluentUI / AntBlazor 两侧 `UIService` 的所有构造点。机械但面广，需一次性做完。

### R3（1 处）

`Common/ExpressionHelper.cs:23` —— `type.GetProperty(prop.Name, prop.PropertyType)`，报 **IL2090**
（`'this'` 需要 `DynamicallyAccessedMemberTypes.PublicProperties`，泛型参数 `T` 没有对应标注）。
注意是 **IL2090 而不是 IL2070**：因为 `this` 是 `typeof(T)`（泛型参数）而非普通变量。

两条修法：
1. 给 `ExtractProperty<T, TValue>` 的 `T` 加 `[DynamicallyAccessedMembers(PublicProperties)]`
   → 级联到 `TPropModel` / 所有 `Set<TMember>(Expression<Func<TPropModel,TMember>>)` 调用方。
2. **直接删掉这次重取**（推荐）：`prop` 本来就是表达式树给出的 `PropertyInfo`；
   `Expression.Property(expr, prop)` 允许 `prop.DeclaringType` 是 `expr.Type` 的**基类**，
   所以继承属性（如 `DefaultProp.Label`）不需要重取。
   唯一语义差异：`new` 隐藏成员时会取"派生类声明"而非"表达式静态类型对应的声明"——
   而按静态类型解析本来就更正确。改动前需确认无显式接口实现/属性隐藏的依赖。
