## P0 重定级：Expression.Compile 不是 AOT 硬阻塞（用户纠正 + 实验证实）

用户给出实测结论：**AOT 场景下 `Expression.Compile()` 可以运行**（前提是类型裁剪安全）。
据此重新推导 09-06 盘点里的 5 项 P0，结论是**原定级错误**——5 项里只有 1 项是真硬阻塞。

### 正确的风险分类（替代原来笼统的"P0"）

- **R1 动态代码生成** → **不致命**。WASM AOT 走 Mono AOT、解释器始终在；
  .NET Native AOT 官方文档亦称"System.Linq.Expressions 始终使用解释形式"。
  **本次实验修正**：`Expression<TDelegate>.Compile()`（强类型泛型形式，即
  `Expression.Lambda<Func<T>>(body).Compile()`）**不带 `[RequiresDynamicCode]`**——
  在 ClientCore 上开启 `-p:IsAotCompatible=true` 后，全部 100 条告警里
  **没有任何一条提到 Compile**，`BindableComponentBuilder.cs` 零命中。
  带该特性的是**基类** `LambdaExpression.Compile()` / 非泛型 `Expression.Lambda(body, params)`。
  ⇒ 判断某处 `Compile()` 是否有 IL3050 风险，要看**静态类型是不是 `LambdaExpression`**。
- **R2 运行时泛型实例化**（`MakeGenericMethod` / `MakeGenericType`，实参含值类型）→ **真硬阻塞**。
  分析与实测均指向报 **IL3050 + IL2060**。引用类型走共享泛型，一般安全。
- **R3 字符串反射 + 裁剪**（`GetMethod("X")` / `GetProperty("X")` / `GetCustomAttribute<T>()` /
  `Expression.Property(expr, "X")`）→ 不崩但**静默失败**，报 IL2075/IL2070/IL2072/IL2026。
  用 `[DynamicallyAccessedMembers]` / `[DynamicDependency]` / 源生成器标注即可，不必重构。

**判据：看有没有 `MakeGeneric*`，而不是看有没有 `Compile()`。**

### InputBuilder 原实现的真实行为（修正上一版错误判断）

上一版误判为"可空数值列会违反 `new()` 约束而抛 ArgumentException"——**错的**。
`Nullable<T>` 是值类型，**满足** `where T : new()`；且 `MakeGenericMethod(col.DataType)` 的实参
就是 `Bind` 期望的 `Expression<Func<T?>>`，类型精确匹配。所以原实现的可空数值/可空日期**是能工作的**。

真正不工作的只有两处，且旧实现同样抛异常：
1. **可空 bool**：`IUIService.BuildSwitch` 是非泛型、固定 `bool`，没有 `bool?` 重载。
   旧实现靠 `Expression.Convert` 的参考转换骗过编译期，运行时 `InvalidCastException`。
2. **非 string 的 Text/Password 列**（如 `Guid`、`char`、`TimeSpan`、`DateTimeOffset`）：
   旧实现 `Expression<Func<Guid>>` → Convert 到 `Expression<Func<string>>` → 运行时 `InvalidCastException`。

## 落地：EnumHelper 去反射，复用 EnumDisplayProviderGenerator（已完成并验证）

诉求：改造 `Utils/EnumHelper.cs`，复用既有 Enum 生成器产物。

### 关键判断：既有 ILookupProvider 不够用

`EnumDisplayProviderGenerator` 原先只产 `{Name}LookupProvider : ILookupProvider`：

- 按**枚举简单名**（string）为键 —— 因为消费方 `ColumnInfo.LookupType == enumType.Name`；
- **只收录带 `[Display]` 的成员** —— 服务于表单下拉的"可选项"语义；
- 值域是 `LookupEntry(string Code, string DisplayName)`，**丢类型**，且是实例（走 DI）。

而 `EnumHelper<TEnum>` 是**静态**入口（`FluentEnumSelect.OnInitialized` 里
`OptionText = EnumHelper<TEnum>.GetDisplayName`），语义是"枚举字典"：**全部成员**（无 `[Display]` 回退成员名）、
需要**强类型值数组**。⇒ 复用不了 ILookupProvider，改为**同一个生成器多产一个接口**（不新增生成器）。

### 设计

- 新增 `Lockup/EnumMeta.cs`：`IEnumMeta { Array Values; IReadOnlyDictionary<string,string> DisplayNames; string? GetDisplayName(object); }`
  + `EnumMetaRegistry`（`ConcurrentDictionary<Type, IEnumMeta>`）。
  **按 `Type` 为键**：枚举简单名会跨命名空间重复，而 `typeof(TEnum)` 在 AOT 下是安全常量。
- 生成器 `BuildEnumMeta`：对**每个**能写出 `typeof()` 引用的枚举产 `{Name}EnumMeta`，用 `[ModuleInitializer]` 自注册。
  `Values` 用**强类型数组**承载、以 `Array` 暴露，消费侧靠**拆箱**而非泛型实例化 ⇒ 不引入 `MakeGenericMethod`。
- 模块初始化器的**时序安全性**：`EnumHelper` 和它覆盖的枚举同在一个程序集/模块，模块初始化器
  先于模块内任何类型访问运行；跨程序集（如 `Vip`）时消费方代码本身就在那个程序集里，同样安全。
- `BuildProvider`（原 ILookupProvider 路径）**原样保留**，仍只在有 `[Display]` 时生成。
  两类产物刻意分开，不动既有下拉行为。

### EnumHelper 新实现（`Utils/EnumHelper.cs`）

| 成员 | 原实现（反射） | 现实现 |
|---|---|---|
| `GetValues()` | `Enum.GetValues(enumType).Cast<TEnum>()` → IL3050 | 读 `meta.Values`，逐项 `(TEnum)item` 拆箱 |
| `GetDisplayName(v)` | `Enum.GetName` + `GetField().GetCustomAttribute<DisplayAttribute>().GetName()` → IL2075 | meta 的 switch 查表；无 `[Display]` 返回 null |
| `ParseDictionary()` | `Enum.GetValues` + `GetMember()[0].GetCustomAttribute<...>()?.Name ?? name` | `new Dictionary<>(meta.DisplayNames)` |
| `Parse(s)` | `Enum.TryParse(enumType, s, out object)` | **原样保留** |

**`Parse` 为什么可以不动**：实测 `Enum.TryParse(Type, string, out object)` **零告警**
（未标 `[RequiresDynamicCode]`），所以名字 / 数字串 / `Flags` 逗号串语义**完整保留**。
`enumType` 由 `Nullable.GetUnderlyingType` 推出，故 `EnumHelper<LayoutMode?>` 也命中同一枚举的 meta
（`(TEnum)item` 从装箱的 `T` 拆到 `T?` 是 CLR 合法操作）。

### 覆盖范围与边界

## 重构 v2：IEnumMeta 作为唯一底层，provider 由通用适配器取代逐枚举生成（已完成并验证）

用户追问两点：① `IEnumMeta` 能否泛型化；② 能否让原枚举生成器直接复用 `IEnumMeta`，
不要为了多产一个接口而显得割裂——`IEnumMeta` 应当成为 `LookupEntry` 的**更底层依赖**。

### ① 泛型化：否，理由硬

`IEnumMeta<TEnum>` 走不通，两条路都死：

| 路径 | 后果 |
|---|---|
| 给 `TEnum` 加 `where TEnum : struct, Enum` | `EnumHelper<LayoutMode?>` 编译不过。`FluentEnumSelect<TEnum>` 用 `[Parameter] TEnum? EnumValue` 承载绑定值，**刻意不加约束**，可空枚举类型实参是合法用法；`BuildSelect<TValue>` 同理 |
| 运行时 `MakeGenericType(enumType)` 构造 | **IL3050 + IL2060 —— 正是本次治理要消灭的 R2 硬阻塞** |

⇒ 注册表必须按**运行时 `Type`** 查表（简单名会跨命名空间撞），而泛型实参无法静态确定。
**`IEnumMeta` 的类型擦除是承重的，不是随手写的。** 泛型只该出现在实参能静态写死的地方（provider 层）。

### ② 统一：是，且这次找到了"割裂"的源头

`Lockup/EnumLookupProvider.cs` 里原本躺着一个**废弃空壳** `class EnumLookupProvider : ILookupProvider`
（`TypeName => ""`、构造出空字典），`ServiceCollectionExtensions.cs:29-34` 还留着注释残骸：

```csharp
//public static IServiceCollection AddEnumLookupProvider<TEnum>(this IServiceCollection services)
//    where TEnum : struct, Enum
//{ services.AddSingleton<ILookupProvider, EnumLookupProvider>(); }
```

⇒ **原架构本就是"一个通用 provider + 按枚举泛型注册"**，生成器后来把它替换成了 N 个 per-enum provider 类，
却把空壳和注释留在了原地。所以"统一"不是新增设计，是**回归原始意图**。

### 最终分层（`IEnumMeta` 在 `LookupEntry` 之下）

```
生成期（每枚举一个类）
  {Name}EnumMeta : IEnumMeta —— Fields(全成员+值+标签) / DisplayNames / GetDisplayName
        │  [ModuleInitializer] 注册
        ▼
  EnumMetaRegistry（Type → IEnumMeta，类型擦除）
        │
        ├──► EnumHelper<TEnum>           "枚举字典"：全部成员，缺 [Display] 回退成员名
        └──► EnumLookupProvider<TEnum>   "可选项"：只收录带 [Display] 的成员
                    │
                    ▼
             LookupEntry → LookupService（TypeName = typeof(TEnum).Name）
```

- `EnumField(object Value, string Name, string? Label)`——**Label 必须保留 nullable**。
  若只存合并后的显示名，"全成员"与"仅 [Display] 成员"两种语义就无法在同一份数据上区分，
  又会退化成两个集合各解析一遍（那才是真正的割裂）。
- `EnumLookupProvider<TEnum> where TEnum : struct, Enum`——**唯一**的枚举 provider 实现，
  `TypeName => typeof(TEnum).Name`（对齐 `ColumnInfo.LookupType = enumType.Name`）。
  创建它的地方是生成代码，实参就是具体枚举名，所以泛型实例化编译期可定，**不引入 `MakeGenericType`**。
- 生成器**删掉了整个 `BuildProvider` 分支**，只产 `{Name}EnumMeta.g.cs`（hintName 由 `{X}.Enum.g.cs` 改为 `{X}EnumMeta.g.cs`）。
  无 `[Display]` 成员时不写 `LookupService.AddEnumProvider(...)` 那行，等价于原来"不生成 provider"。
- 生成语法一律取**保守形式**（显式 `new EnumField(...)`、不用集合表达式 / 目标类型 `new`），
  因为产物要在**消费方项目**里编译，而这是模板仓库、消费方 LangVersion 不可控。
