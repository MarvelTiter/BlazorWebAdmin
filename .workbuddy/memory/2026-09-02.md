## BlazorWebAdmin AOT 就绪度分析

- **当前状态**：BlazorAdmin.Client（BlazorWebAssembly SDK，net8.0/net10.0）未启用 WASM AOT，共享 props（projects.versions.props / pack.settings.props）中无 RunAOTCompilation/PublishAot/Trim 配置，默认解释器模式运行。
- **风险点（源码扫描确认）**：
  1. [高] SelectComponentBuilder.cs:60,72 `Expression.Lambda(...).Compile()` 动态编译数据绑定——AOT 最不友好模式。
  2. [中] EmbeddedJsonLocalizerFactory.cs:106 `Assembly.GetEntryAssembly().GetReferencedAssemblies()` + `Assembly.Load` 运行时加载程序集读本地化 JSON 资源。
  3. [中] SelectComponentBuilder.cs:94,110 `MakeGenericMethod`（Enumerable.ToList/ToArray）反射。
  4. [中] 反射式属性驱动的页面/权限系统（PageGroupAttribute/PageInfoAttribute + GetCustomAttribute）。
  5. [低] Roslyn 源生成器（SvgContent/EnumDisplay Generator）——生成源码，AOT 友好。
  6. [低] Blazor JS 互操作（JSInvokable/DotNetObjectReference）——AOT 友好。
- **外部依赖注意**：LegacyBlazorJs 仅在 BlazorAdmin(服务端) net10.0 引用，不在 Client，不影响 WASM AOT；LightORM 在服务端项目，WASM AOT 只影响 Client。
- **就绪度结论**：约 35%，需较多改造方可安全启用 AOT。已通过内联 SVG 可视化呈现。
- **启用建议（待用户决策）**：若要启用，优先改造 #1（为数据绑定提供预编译赋值路径或 DynamicDependency 标注）、#2（改用编译期已知程序集列表 + JsonSerializerContext）、#3（用泛型静态方法替代 MakeGenericMethod）。

## 反射改源生成器价值评估（不追求 AOT）

- **关键发现**：项目已重度使用源生成器——AutoInjectGenerator（[AutoInject]）、AutoWasmApiGenerator（GeneratedApiClientDelegatingHandler）、AutoPageStateContainerGenerator（[SaveState]）、EnumDisplayProviderGenerator、SvgContentClassGenerator。故"反射改生成器"是补齐而非引入新范式。
- **判定标准**：反射操作的对象在编译期是否已知 → 已知则改，运行时才知则不改。
- **改造清单（按收益排序）**：
  1. [改·高] TableColumnContext.cs:20 GenerateColumns——实体列定义（ColumnDefinition/Form/Display/ColumnTag 特性 + 属性访问器），最典型生成器目标。
  2. [改·高] ProjectInit.cs:89 ScanRazorLibraryAssembly——Assembly.Load 扫 [Route] 收集程序集，生成静态注册表。
  3. [改·中] ModelPage.cs:51 IsOverride——GetMethod 判断子类是否 override 虚方法，生成静态能力标志。
  4. [改·中] EmbeddedJsonLocalizerFactory.cs:106——资源清单 + LangName 映射表。
  5. [部分·中] InputBuilder.cs:71 GetInputType——DataType→BuildXXX 泛型分派可生成，属性访问（运行时字符串名）仍需反射。
  6. [不改·低] ConditionUnitHelper.cs:88 BuildExpression——查询条件是运行时字符串，反射是本质需求。
  7. [不改·低] PropComponentBuilder.cs:46 PropertySetter——已有缓存+表达式树，收益低。
- **收益定性**：性能属"首帧/首次交互"级改善（反射多已有 ConcurrentDictionary 缓存）；真正大头是类型安全、健壮性（消除 Assembly.Load 脆弱性）、编译期错误检查、为未来 AOT 铺路。
- **建议实施顺序**：先 1 再 2，均为启动/首渲染路径。

## 反射改源生成器落地（TableColumnGenerator）

- **目标**：把 `TableColumnContext.GenerateColumns` 的反射路径（GetProperties/GetCustomAttribute/Expression.Compile）换成增量源生成器，反射保留为兜底。
- **新增项目** `src/Shared/BlazorTemplates/TableColumnGenerator/`（netstandard2.0 Roslyn 组件，`Microsoft.CodeAnalysis.CSharp 4.9.2`），参照已有 EnumDisplayProviderGenerator / SvgContentClassGenerator 的 `[ModuleInitializer]` + `AddSource` 注册模式。
- **改动文件**：
  - `ColumnInfo.cs`：新增 `ColumnInfo(string label, string propertyName, Type dataType)` 构造器 + 公开 `SetAccessors(getter, setter)`，让跨命名空间生成代码注入访问器。
  - `TableColumnContext.cs`：新增 `generatedColumnFactories` 字典 + `RegisterGeneratedColumns`，`GenerateColumns` 命中生成注册表则直出，否则回落 `GenerateColumnsReflection`（原反射缓存逻辑）。
  - `BlazorTemplate.ClientCore.csproj`：以 `OutputItemType=Analyzer` + `PackagePath=analyzers/dotnet/cs` 打包引用生成器 dll。
  - `BlazorAdmin.slnx`：加入新项目。
- **关键坑（已解决）**：
  1. 源码枚举的 `TypedConstant.Value` 是底层数值（Int32）而非 IFieldSymbol，需 `ConstantValue` 反查成员名（InputType/ColumnTag 枚举参数）。
  2. 可空类型属性生成 getter 需用 `((T)o).Prop!` 避免 CS8600/CS8603。
  3. 反射语义对齐：派生类先/基类后按声明序、排除 static 与 indexer、internal-set 仅同程序集可生成 setter、init-only/无 setter 生成 null setter、同名 ColumnTag 取第一个。
- **验证结果**：ClientCore 构建 0 错误；生成 `TableColumnRegistry.g.cs` 约 964 行，注册 7 个实体（ClientInfo/MinimalPermission/TemplatePermission/TemplateRole/TemplateRunLog/UserPwd/TemplateUser），值类型/枚举装箱转型、只读属性 null setter 均正确。
- **未做（后续候选）**：ProjectInit.cs ScanRazorLibraryAssembly（[Route] 静态注册表）、ModelPage.cs IsOverride（静态能力标志）。
