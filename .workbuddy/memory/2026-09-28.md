## Ant 弹窗「点 Ok/取消没反应」修复

**现象**：弹窗架构重构后（去 DialogTemplate + IDialogContent），Ant 侧 `ShowDialogAsync` 点 Ok/Cancel 无反应。

**根因**：Ant 侧 `ModalOptions.OnOk`/`OnCancel` 回调里，只 `tcs.TrySetResult`/`TrySetCanceled`，**没调 `modalRef.CloseAsync()` 关闭弹窗**。导致点按钮后 tcs 虽被设置、但弹窗没关，看起来「没反应」。

**修复**：`OnOk` 回调里校验通过 → `tcs.SetResult` + `await modalRef.CloseAsync()`；`OnCancel` 回调 → `OnCancelAsync` + `tcs.SetCanceled` + `CloseAsync()`。校验失败（`OnOkAsync` 返回 false）不关闭，弹窗保留。

### AntDesign 1.6.2 的弹窗 API 关键事实（实测确认，务必记住，别再踩）

1. **`ModalOptions.OnOk`/`OnCancel` 的类型是 `Func<MouseEventArgs, Task>`**（参数是 `MouseEventArgs`，**不是** `ModalClosingEventArgs`）。编译报 CS1503「无法从 MouseEventArgs 转 ModalClosingEventArgs」就是这个坑。
2. **`ModalClosingEventArgs`（带 `Cancel` 属性）是 `FeedbackComponent<T>` 模板组件路径的方法参数**（`OkAsync(ModalClosingEventArgs)`/`OnFeedbackOkAsync(ModalClosingEventArgs)`），**不是** `ModalOptions.OnOk`。只有走 `@inherits FeedbackComponent` + `ModalService.CreateModalAsync<T>(options, data)` 模板组件路径时才能用 `args.Cancel = true` 阻止关闭。
3. **`ModalRef`（非泛型，`CreateModal(ModalOptions)` 返回）只有 `OpenAsync`/`CloseAsync`/`UpdateConfigAsync`/`SetConfirmLoading`，没有 `OkAsync`**。`ModalRef<T>.OkAsync(T)`/`CancelAsync(T)` 是泛型版（`CreateModalAsync<T>` 返回）才有的。
4. **「校验失败阻止关闭」**在 `ModalOptions.OnOk`（MouseEventArgs，无 Cancel）路径下，只能靠「校验失败时不调 `CloseAsync()`」实现（回调执行完，若不调 CloseAsync 弹窗保持打开）。
5. `ModalRef.CloseAsync()` 是程序化关闭，**不递归触发** `OnOk`/`OnCancel` 回调（那些是用户点按钮时的事件）。

### 结论
- 框架用 `ModalOptions.OnOk`（MouseEventArgs）+ 显式 `modalRef.CloseAsync()` 控制关闭，与 FluentUI 侧（footer `OnClickAsync(IDialogInstance)` → `instance.CloseAsync`）语义对齐。
- 若未来需要「校验失败 + args.Cancel」的精细控制，需改用 `FeedbackComponent<T>` 模板组件路径（`ModalService.CreateModalAsync<T>`），但这会引入 `FeedbackComponent` 基类耦合，暂不需要。
